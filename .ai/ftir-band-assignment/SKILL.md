# FTIR Band Assignment

Работай как система поддержки интерпретации, а не как база точной идентификации.
Всегда разделяй наблюдение, справочное совпадение, химическую гипотезу и степень
уверенности. Не подменяй измеренный спектр ожидаемыми справочными значениями.

## Жёсткие ограничения

- Не утверждай конкретное вещество по одному FTIR-спектру. Формулировки: «совместимо с», «поддерживает», «возможная группа».
- Не перемещай наблюдённый пик к центру справочного диапазона.
- Не создавай пик только потому, что для группы есть подходящий диапазон.
- Для каждого пика перечисляй существенные альтернативы и отсутствующие подтверждающие полосы.
- Fingerprint-зону используй преимущественно как подтверждение; не делай по ней единственную идентификацию.
- Для смеси, полимера, плохого baseline или слабого сигнала понижай уверенность и явно указывай ограничение.

## Вход

Принимай список пиков, JCAMP-DX/JCM (`.dx`, `.jdx`, `.jcm`, `.jsm`), CSV/TSV с
`wavenumber, signal` или изображение спектра.
Для изображения координаты помечай как приблизительные, если они сняты вручную.
Если неизвестно, уточни `%T` или absorbance, направление оси, единицы, среду,
разрешение и возможные фоновые полосы.

## Численная обработка JCAMP и CSV/TSV

В браузерном приложении сначала используй существующий JCAMP-DX/JCM-парсер
`app.js`/`jcampconverter`. Он уже нормализует `.dx`, `.jdx`, `.jcm`, `.jsm` и
fallback-форматы в пары `wavenumber, signal`. Для отдельного офлайн-детектора
используй [peak.py](../../peak.py) на этом нормализованном CSV/TSV:

```bash
python peak.py normalized-spectrum.csv [--transmittance] [--thresh 0.03] [--top 30]
```

`peak.py` читает нормализованные пары, сортирует ось FTIR, переводит `%T` в
absorbance, применяет лёгкое сглаживание, ищет локальные максимумы, оценивает
заметность и FWHM. Сохраняй исходную координату и не считай результат detector
окончательным. Не создавай второй независимый JCAMP-парсер без необходимости:
это может дать расхождения с тем, что видит пользователь в графике.

Перед интерпретацией проверь минимум пять строк, единицы, равномерность сетки,
пропуски, тип сигнала, направление оси, baseline и не смешаны ли несколько серий.
Пороги detector являются стартовыми, а не универсальной калибровкой прибора.

## Обязательный протокол

1. Нормализуй координаты к `cm^-1`; для длины волны используй `ν = 10000 / λ`.
2. Для каждого пика запиши `nu`, интенсивность, форму, ширину, источник (`manual`, `peak.py` или `image`) и качество измерения.
3. Сначала проверь артефакты из `references/diagnostic_zones.md`, раздел 0.
4. Выполни зонный скан: X-H `4000–2500`, тройные связи `2500–2000`, C=O `1850–1630`, C=C/ароматика `1690–1450`, fingerprint `1300–400`.
5. В `references/bands_master.md` найди ВСЕ диапазоны, содержащие `nu ± 15 cm^-1`; для broad используй `nu ± 30 cm^-1`. Не выбирай первую строку. `peak-db.js` можно использовать только как грубую UI-подсказку, не как канонический источник.
6. Ранжируй кандидатов по совпадению диапазона, форме, ожидаемой интенсивности, companion-полосам и противоречиям. Близость к центру диапазона только помогает сортировке.
7. Собери гипотезы из якорной полосы и подтверждающих полос. Отсутствие обязательного companion снижает уверенность.
8. Сильные полосы учитывай раньше слабых. Не трактуй интенсивность как концентрацию без калибровки.
9. Заверши списком неотнесённых пиков, артефактов, альтернатив и нужных дополнительных измерений.

## Полезные корреляции

Используй `references/diagnostic_zones.md` для карбонильной лестницы, артефактов,
ароматических паттернов и companion-пар. Проверяй эфир, спирт, амид, альдегид,
ангидрид, нитрил, кислоту и ароматику по соответствующим якорям и подтверждениям.
Не путай broad O-H с N-H, воду около `1640` с C=C, а слабые обертоны бензола
в `2000–1650` с карбонилом.

## Уверенность

- `high`: сильный якорь в характерном диапазоне, минимум одна подтверждающая полоса, противоречий нет.
- `medium`: якорь есть, но диапазон перекрывается или подтверждение неполное.
- `low`: одиночная, слабая, broad или плохо разрешённая полоса; альтернативы равноправны.

Не превращай эти уровни в проценты без валидированной статистической модели.

## Машинный результат

При интеграции возвращай только JSON со схемой версии `1.0`:

```json
{
   "version": "1.0",
   "observations": [{
      "nu": 1735,
      "intensity": "s",
      "shape": "sharp",
      "width_cm1": 18,
      "source": "peak.py",
      "candidates": [{
         "assignment": "C=O stretching",
         "class": "ester or aldehyde",
         "reference_range": "1750-1730",
         "evidence_for": ["strong band"],
         "evidence_against": ["aldehyde doublet not observed"],
         "confidence": "medium",
         "source_ref": "bands_master.md"
      }]
   }],
   "hypotheses": [],
   "unassigned_peaks": [],
   "artifacts": [],
   "limitations": []
}
```

LLM может ранжировать и объяснять кандидатов, но не должна менять `nu`,
автоматически подтверждать пики или удалять existing confirmed stripes.
Результат сначала получает статус `candidate`; принять его может только пользователь.

## Формат человекочитаемого ответа

1. Таблица: `nu | интенсивность | форма | кандидаты | диапазон | уверенность`.
2. Гипотезы по убыванию уверенности: что подтверждает и что противоречит.
3. Неотнесённые пики и вероятные артефакты.
4. Ограничения и необходимые подтверждения: эталонный спектр, NMR, MS или другой метод.

## Безопасность API и деплой

- Не помещай API-токены Gemini/Mistral в `app.js`, `index.html`, `.ai`, `.env` в Git или frontend bundle.
- Браузер вызывает только backend endpoint, например `/api/analyze`; backend читает ключ из переменной окружения.
- В GitHub Actions храни ключ в `Settings -> Secrets and variables -> Actions`; передавай его в deploy step как secret/env и не печатай в логах.
- На сервере используй secret manager платформы или encrypted environment variables.
- Добавь `.gitignore` для `.env`, `.env.*`, credentials и временных файлов; `.env.example` содержит только имена переменных.
- Ограничь размер запроса, rate limit, timeout, стоимость и логирование. Не логируй полный спектр и prompt по умолчанию.
- Валидируй JSON ответа модели на backend и удаляй неожиданные поля.
- Для публичного GitHub-репозитория включи secret scanning/push protection и ротируй ключ при подозрении на утечку.
